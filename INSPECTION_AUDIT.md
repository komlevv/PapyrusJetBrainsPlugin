## Policy resulting from this audit

- Do not edit or “clean up” the vendored VSIX merely to satisfy CLion inspections.
- Do not edit generated Starter/CLion diagnostic, telemetry, report, event-stream, or log files.
- Do not hide real plugin-source warnings with global inspection exclusions.
- A suppression is acceptable only when the warning is caused by an unavoidable external/platform contract and the suppression is attached to the smallest possible declaration with an explanatory comment.
- The regression target after this cleanup remains **51 UNIT + 11 PAPYRUS-LANG + 33 REAL CLION UI = 95 tests**.

## Fresh IntelliJ IDEA inspection pass — 0.2.139

The post-0.2.138 inspection run reported 237 warnings, 7 debugger suggestions, and 13 weak warnings. The screenshots supplied for this pass expose only part of the large `Declaration redundancy` subtree, so 0.2.139 fixes or classifies the visible deterministic findings first; the remaining collapsed findings must be re-exported after this pass.

Behavior-neutral fixes in 0.2.139:

- removed the now-redundant `UnstableApiUsage` suppression from `GeneralCommandLine.createProcess(...)`; exact Platform 262 declares this as the supported override hook;
- removed the redundant `FieldMayBeFinal` suppression from `PapyrusSettings.SettingsState` while keeping the state bean mutable, matching JetBrains `PersistentStateComponent` serialization guidance;
- aligned `TextMateBundleProvider.getBundles()` and tree-node `toString()` nullability with non-null contracts;
- removed a redundant Run Configuration local and redundant `ExpandVetoException` declaration;
- guarded nullable compiler-diagnostic test results with `assertNotNull`;
- avoided a repeated nullable `AccessibleContext` lookup and factored the duplicated project-root VFS lookup;
- used Java 25 `StringBuilder.repeat(...)`;
- specialized the Windows Job lifecycle test helper whose class arguments were constant;
- reformatted the Markdown tables flagged by the IDE;
- rephrased the Settings label to sentence style without lowercasing the Creation Kit/Skyrim product names.

Intentional findings are not converted into behavior changes:

- JNA `Kernel32JobApi` methods retain their real Win32 `BOOL` return types; `UnusedReturnValue` is suppressed on the native interface instead of changing ABI-significant signatures;
- `PapyrusHostGuardianMain` and the Windows Job test retain bounded `Thread.sleep` polling because the loop simultaneously watches a filesystem gate/process death or test process state; `BusyWait` is narrowly suppressed;
- raw server/Windows Job tests retain local `java.nio.file.Files` calls; the Platform 262 Eel inspection is aimed at remote plugin filesystems, while these fixtures are deliberately local Windows process/filesystem contracts;
- the `uiIntegrationTest -> main` dependency remains because the custom-compiled Kotlin UI harness imports `WindowsKillOnCloseJob`; IDEA's module-dependency warning does not model that custom Kotlin compilation path;
- Gradle `println` entries are debugger logpoint suggestions for intentional build diagnostics, not code-quality defects;
- the Java 25 launcher no longer requires `public` on `main`; the two JDK-only launcher methods use package access to match the active Java 25 target;
- action-description capitalization around the proper names `Papyrus` and `Skyrim Special Edition` is an inspection limitation; the resource entry carries a narrow `PluginXmlCapitalization` suppression.

## 0.2.144 UI-startup root-cause correction

Exact Platform 262 `ProjectManager.kt` defines `isProjectOpened()` as an initialized project with a showing IDE frame. It does not mean that CLion first-run modal UI has appeared or completed. 0.2.142/0.2.143 waited for `wizardVisible || isProjectOpened`; when project-open became true first, the code immediately skipped the wizard branch and later became blocked when `Open Project Wizard` appeared. 0.2.144 removes that OR-condition race and restores the 0.2.138–0.2.141 ordering: bounded wizard discovery independent of project-open state, dialog-owned `okButton`, existing dialog-settle wait, then the established project poll. A diagnostic wrapper records whether the wizard is still open and the open-project count only if the pre-existing settle wait times out; it does not alter the successful control flow.

## 0.2.145 offline AST lint cleanup

After the user-verified 0.2.144 **114/114** gate, a separate offline static pass was run with the JDK compiler AST over plugin-owned Java roots only (`src/main`, `src/test`, `src/serverIntegrationTest`, `src/uiIntegrationTest`). This is a local heuristic used to prioritize review; it is **not SonarQube/PMD/Checkstyle** and its severity labels are not treated as authoritative defects.

Before cleanup: **28 MAJOR / 65 MINOR / 143 INFO = 236 findings**. After the behavior-preserving cleanup: **13 MAJOR / 66 MINOR / 143 INFO = 222 findings**. The MINOR count increases by one because several former `Throwable` catches are now correctly narrowed to `RuntimeException`, which the heuristic classifies as a lower-severity broad catch.

Fixed high-confidence findings:

- `PapyrusRenameHandler.buildEditPlan()` was decomposed into document/edit/range/overlap validation helpers while preserving the complete pre-write safety contract and messages.
- `PapyrusHostRuntimeStager` now represents the immutable-fingerprint publication race explicitly with `FileAlreadyExistsException` instead of comment-only catch bodies.
- optional Creation Kit INI read failures and temporary Pyro snapshot deletion failures remain non-fatal but are visible through Platform 262 `Logger` debug output.
- user-facing assembly and project-build boundaries no longer catch arbitrary `Throwable`; `PapyrusProjectTaskRunner` completes its `AsyncPromise` exceptionally and rethrows JVM `Error` rather than leaving a pending promise or treating the error as a normal build failure.
- `PapyrusManagedHostCommandLine` and raw-server containment cleanup preserve the original startup failure, attach secondary cleanup failures as suppressed exceptions, and rethrow the original `IOException`, `RuntimeException`, or `Error`.

Remaining MAJOR heuristic findings are intentionally not mechanically changed: the standalone guardian's JDK-only `System.exit`/best-effort gate deletion; `PapyrusUiTestSupport`'s EDT failure-transport `Throwable` catch; data-heavy/large integration-test classes; expected best-effort close/symlink/Robot cleanup in tests. These require a separate semantic refactor or are deliberate boundary behavior, not a reason for fake no-op statements or global suppressions.
